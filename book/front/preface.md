# Preface

This repository is a leaderless, multi-region object store written in Go on the standard library alone, with `pgregory.net/rapid` restricted to test files. Every protocol claim about fault tolerance, repair, or convergence is backed by deterministic simulation testing, property tests, and fuzzing. Metadata updates use optimistic concurrency control for conditional writes; when concurrent writes collide across a partition, last-writer-wins settles the conflict and every discarded write is counted and logged.

This book explains each distributed-systems mechanism in plain terms and shows where it lives in the repository. It assumes you are a working engineer with no prior knowledge of this code.

Read the book with the repository open beside it. Every chapter follows the same layout: the core idea and terminology, how it maps to packages and files (along with design choices, their costs, and how the simulator exercises them), three to five short code excerpts taken directly from the source, what the tests prove and what they do not, and pointers to files, commands, and papers for further reading. If you want to jump straight from a topic to its packages and test targets, start with the [Topic Map](topic-map.md).

The chapters follow the order of dependencies, starting with [Deterministic Simulation Testing](../chapters/01-deterministic-simulation.md). The simulator comes first because every protocol package is written against `internal/env` — virtual time, seeded random streams, a fault-injecting transport, and a two-layer disk — so crashes, partitions, bit-rot, and rare timing bugs replay byte for byte from a single seed before real sockets enter the picture. Five standalone protocol chapters build over that boundary: [SWIM Gossip Membership](../chapters/02-swim-gossip.md), [Reed-Solomon Erasure Coding](../chapters/03-reed-solomon-erasure-coding.md), [Merkle-Tree Anti-Entropy](../chapters/04-merkle-anti-entropy.md), [Optimistic Concurrency Control](../chapters/05-optimistic-concurrency-control.md), and [Sagas](../chapters/06-sagas.md). [The Object Store and Sync Engine](../chapters/07-object-store-and-sync-engine.md) wires all five into one node core behind real sockets, OS files, the object API, and `objnode`. Finally, [End-to-End Tests and Hardening](../chapters/08-end-to-end-and-hardening.md) runs whole-cluster scenarios on both the simulator and real `objnode` processes under nemesis cycles and fuzzing.

This is not production software. It omits authentication, transport encryption, streaming object I/O, tombstone garbage collection, automatic re-placement of permanently lost nodes, and takeover for a dead migration coordinator. Each chapter states its exact boundaries under its narrowed claims and what the tests do not prove.
