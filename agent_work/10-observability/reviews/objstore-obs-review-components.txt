FINDINGS
F1 [IMPORTANT, cost] internal/storage/metrics.go:100-118 enableMetrics (called from storage.NewNode, node.go NewNode) lists and fully Reads every blob under blobPrefix on every construction. node.scope() (internal/node/node.go:547-553) and migrator.copier() (internal/node/migrate.go:212-218) construct a NEW storage.Node per region at runtime on the owner loop and only afterwards ShareMetrics() over the freshly scanned (discarded) state. Reproducer: overlay probe above: 3 consecutive NewNode over 50 blobs = 50 disk reads each; with R regions a first cross-region operation or migration triggers R extra full-disk reads inside the loop (O(disk) work, synchronous, no budget). Violates "no unbounded scan"/O(1) hot-path cost; only when metrics enabled. Fix: skip the inventory scan when a shared owner is supplied (e.g. build scoped nodes with MetricsEnabled and a constructor/option that takes the owner's metricState+sizes, or defer enableMetrics to ShareMetrics), and ideally use a size-only List instead of reading blob bodies at the owner's startup. Note correctness is otherwise right because ShareMetrics overwrites metric/sizes.
F2 [NIT] internal/storage/metrics.go:119-129 observedPut counts shard_bytes_total{write} and sets sizes for every nil-return Put, including the idempotent identical-blob path (chunkstore.go ~108-114, no bytes written) -> over-count; and a Put whose Write succeeded but Sync failed returns error without updating sizes/local_* gauges though the blob is in the written layer (gauge drift until restart). PLAN says "actual accepted bytes".
F3 [NIT] internal/node/objects.go:345 HeadObject is labelled operation="get"; HEAD is also counted when the HTTP layer uses it; PutObject/GetObject async path uses in-flight adjust only (no depth guard), so a nested public sync call inside a put/get callback would count as an extra "other". Decide/document; no test covers HEAD.
F4 [NIT] internal/storage/metrics.go:150-155 Node.ErasureSnapshot and NewCodec/ShareMetrics use unchecked type assertions n.codec.(*erasure.MeteredCodec); safe today (NewNode always builds a MeteredCodec) but panics if StripeCodec is ever swapped; MetricSources() calls ErasureSnapshot on the owner loop.
F5 [NIT] saga_recoveries_total counts terminal logs loaded at startup too (engine.go:678); PLAN wants recovery distinguished from fresh start - arguably only non-terminal recoveries are "recoveries". Pick and document.
F6 [NIT/coverage] no committed test for: inventory aggregate (merkleSnapshot inventoryEntries drift after delete/rebuild), storage Put idempotent/sync-failure accounting, gossip probe timeout->indirect->recovery counters beyond the 65-line metrics_test, saga retry/comp counter exactness is only lightly exercised (50-line test). Behaviour reads correct by inspection and existing protocol suites pass with metrics off; recommend adding the F1 scan-count test as the regression guard.
