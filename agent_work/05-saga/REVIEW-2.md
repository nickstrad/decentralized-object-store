## New findings

1. **NIT — `objects(n)` produces unsorted keys for `n > 1000`, breaking `opPut`'s binary-search precondition above 1000 seeded objects**
   - **File & line:** `internal/saga/sagasim/cluster.go:85-91`, `internal/saga/sagasim/store.go:224,465-472` (also contradicts `agent_work/05-saga/build-notes.md:427` "seeds are generated sorted")
   - **What is wrong:** `objects(n)` formats keys with `fmt.Sprintf("o%03d", i)`. For `n <= 1000` (`o000`..`o999`) the slice is lexicographically sorted, but for `1000 < n <= MaxObjects` (4096), `"o999" > "o1000"`, so `bk.Objs` is not sorted. `opPut` uses `slices.BinarySearchFunc(bk.Objs, kv.Key, ...)` assuming `bk.Objs` is sorted. On a bucket seeded with `objects(MaxObjects - 1)` (4095, as in `TestStoreWritePathEnforcesTheBound`) or `objects(2000)`, overwriting an existing key such as `"o1000"` or `"o500"` misses in binary search and inserts a duplicate key (or falsely fails with `env.ErrTooLarge` when `len(bk.Objs) == MaxObjects`). `TestStoreWritePathEnforcesTheBound` missed this because `"last"` starts with `'l' < 'o'` and lands at index 0; no matrix/nemesis/duel scenario currently seeds >1000 objects or overwrites `"o..."` keys.
   - **Reproduction:** Seed a `Store` with `BucketSeed{Name: Bucket, Loc: "a", Objs: objects(2000)}` and call `ask(s, opPut, Bucket, "o1000", "updated")`: `slices.BinarySearchFunc` compares `"o1000"` against `"o500"` (`'1' < '5'`), searches `[0..499]`, returns `found == false`, and inserts a second `"o1000"` entry (`len(bk.Objs) == 2001`).
   - **Smallest fix:** Sort `sd.Objs` by `Key` in `Store.load` (or format keys with `fmt.Sprintf("o%04d", i)` in `objects(n)`, which stays sorted up to 9999 > `MaxObjects`).

2. **NIT — `NemesisRun` and `DuelRun` reassign the captured `res` parameter when `nil` instead of using a local variable**
   - **File & line:** `internal/saga/sagasim/scenarios.go:55-58, 165-168`
   - **What is wrong:** `if res == nil { res = &NemesisReport{} }` (and the same in `DuelRun`) mutates the outer parameter captured by the returned `func(seed int64) *sim.Sim`. Sequential reuse (`simtest.CheckDeterministic`, `simtest.Sweep`) is safe because `*res = ...` resets it on each call, but invoking a single `NemesisRun(p, nil)` or `DuelRun(p, nil)` closure concurrently from multiple goroutines would race on `res` and `*res`.
   - **Reproduction:** `fn := sagasim.NemesisRun(p, nil)` called concurrently from two goroutines under `go test -race` reports a data race on `res`.
   - **Smallest fix:** Use a per-invocation local pointer (`out := res; if out == nil { out = &NemesisReport{} }`) in `NemesisRun` and `DuelRun`.
